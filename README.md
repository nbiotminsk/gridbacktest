# Массовые бэктесты gridbacktest.com

Нужен Python 3.9+ (при установке отметить «Add python.exe to PATH»).

**Проще всего — двойной клик по `run.bat`**: откроется меню (вход, пробный и основной
прогон, лучшие результаты). `requests` бат поставит сам. С аргументами бат передаёт их
скрипту: `run.bat sweep sweep.json`, `run.bat top -n 50`.

**Графический интерфейс — двойной клик по `gui.bat`** (или `python gui.py`): те же
настройки, что и в `sweep.json`, но в окне, оформленном и подписанном как сайт:

- **Пара и период** — «Пара» открывает окно с поиском, как на сайте, но можно отметить
  несколько пар (или «Все пары» = `all`); сторона Long/Short (можно обе); даты «с/по» или
  кнопки «лет 1…6».
- **Точка входа** — «Всегда в рынке» (с паузой перезахода), «Готовые связки» (выбор из
  списка, интервал, порог swing), «Свои условия» (`indicators`, JSON; кнопка «Пример»).
  Можно включить несколько — переберутся все.
- **Настройки сетки** — таблица параметров сайта с пресетами «Консервативно / Оптимально /
  Агрессивно». У каждого параметра «Значение» (одно или несколько через запятую, дробные —
  через точку) и рядом **«перебор»: от / до / шаг** включительно (до 500 значений; у целых
  параметров шаг целый). Справа — сколько вариантов даёт строка. Границы — лимиты сервера.
  Комиссии — в %, как на сайте.
- **Счётчик комбинаций** под таблицей обновляется сразу при любом изменении: сколько прогонов,
  из чего они складываются (пары × стороны × входы × наборы), сколько уже есть в CSV и
  примерное время при 145 прогонах в час.
- **«Дополнительно…»** — файл результатов, лимиты скорости, `entry_hold`, ещё периоды и `sets`
  (JSON), сохранение/загрузка конфига (загружаются и `sets`, и все периоды).

«Запустить прогон» пишет `sweep_gui.json` и выполняет `python gbt.py sweep sweep_gui.json`
(журнал и кнопки «Стоп», «Лучшие результаты», «Открыть CSV» — в окне). Если CSV уже есть,
обычный запуск спрашивает «продолжить?», а «Продолжить досчёт» досчитывает оставшиеся
комбинации сразу, без вопроса. «Стоп» дописывает прогоны, которые уже идут, и
останавливается; второе нажатие снимает процесс сразу.

То же из командной строки:

```bash
python gbt.py login                  # вход через Telegram -> session.json (живёт ~неделю)
python gbt.py me                     # проверить: статус ботов должен быть active
python gbt.py info                   # пары, связки входа, лимиты параметров
python gbt.py sweep sweep.json --dry-run   # сколько будет прогонов
python gbt.py sweep sweep.json       # запустить перебор
python gbt.py top results.csv -n 50  # лучшие (без ликвидаций; --with-liq, --by max_drawdown)
```

Без входа (или без активного бота Pifagor) сервер отдаёт итоги нулями (`locked`) —
скрипт тогда останавливается.

**Лимиты сервера: 20 прогонов в минуту и 150 за последний час** (дальше — 429 «слишком
часто» / «лимит 150»). Скрипт держит 18/мин и 145/ч (`rate_per_min`, `rate_per_hour`),
помнит время прогонов в `rate.json` (перезапуск не обнуляет часовой счёт) и при 429 сам
ждёт. Поэтому **~145 прогонов в час — это потолок**, `workers` его не поднимают: например,
11 016 комбинаций из `sweep.json` — это около 76 часов. `--dry-run` показывает число прогонов и время.

Прерывание (Ctrl+C) безопасно: каждая строка пишется сразу, повторный запуск
пропускает посчитанное. Изменили конфиг — новые комбинации досчитаются, старые останутся.

## Конфиг (sweep.json)

| поле | что | пример |
|---|---|---|
| `symbols` | пары или `"all"` | `["BTCUSDT","ETHUSDT"]` |
| `positions` | `long` / `short` | `["long","short"]` |
| `periods` | последние N лет пары или даты | `[{"years":4}, {"from":"2022-01-01","to":"2024-12-31"}]` |
| `entries` | `none` (всегда в рынке), id связок или `"all"` | `["none","rsi","bb"]` |
| `entry_tfs` | интервал связки: 15, 30, 60, 240, 1440 или `"all"` | `[60,240]` |
| `swing_levels` | порог связки `swing`, % (0.1–50) | `[1,2,3]` |
| `chart_tfs` | интервал графика — при `none` это пауза перезахода (или `"all"`) | `[60]` |
| `defaults` | неизменные параметры | `{"deposit":1000,"leverage":10,"reinvest":0}` |
| `grid` | списки значений — перебирается декартово произведение | `{"orders":[10,20], ...}` |
| `sets` | явные наборы (добавляются к `grid`) | `[{"orders":15,"price_overlap":25}]` |
| `fees` | комиссии долей единицы | `{"fee_maker":0.0002,"fee_taker":0.0005}` |
| `indicators` | свои правила входа — см. ниже | |
| `entry_hold` | сколько минут после сигнала вход ещё разрешён (можно списком) | `60` |
| `workers`, `rate_per_min`, `rate_per_hour` | параллельность и потолок прогонов в минуту и в час | `2`, `18`, `145` |
| `output` | CSV с итогами (рядом пишется `.jsonl` с полными ответами без свечей) | `"results.csv"` |

Параметры сетки: `deposit`, `leverage` (1–50), `orders` (1–50), `price_overlap` (0.1–90 %),
`price_factor` (0.5–3), `volume_factor` (0.5–3), `profit` (тейк, 0.01–50 %), `reinvest` (0/25/50/100).

## Перебор индикаторов (`indicators`, пример — sweep_indicators.json)

Кроме 16 готовых связок сайта (`entries`) можно задавать свои условия входа из любых
24 индикаторов сайта (`python gbt.py info` — список, параметры и нормы). **Любое поле
может быть списком — переберутся все сочетания.**

```json
"indicators": [
  {"ind": "rsi",        "period": [7, 14, 21], "value": [20, 25, 30], "tf": [15, 60]},
  {"ind": "supertrend", "period": [7, 10],     "mult": [2, 3],        "tf": 240},
  {"ind": "bb",         "period": [20, 30],    "mult": [2, 2.5]},
  {"ind": "big",        "line": ["250k", "1m"], "value": [20, 40]},

  {"all": [ {"ind": "rsi", "value": 30}, {"ind": "vol_spike", "value": [2, 3]} ]},
  {"any": [ {"ind": "rsi", "value": 30}, {"ind": "drawdown", "hours": 4, "value": [2, 3]} ]}
]
```

- Поля индикатора: `period`, `mult`, `line`, `method` (sma/ema/wma), `price`, `hours`, `shift`,
  `tf` (15/30/60/240/1440; по умолчанию — `entry_tfs`), `op` (lt/gt/cross_up/cross_down), `value`.
- `value`/`op` пишутся для **лонга**; для шорта зеркалятся по норме сайта: RSI < 30 → > 70,
  CCI < −100 → > 100, крупные сделки > 20 → < −20. Где норма одна на обе стороны
  (ADX, всплеск объёма) — без изменений. `drawdown` в шорте становится `runup`, как у связки swing.
  Свои значения для шорта: `short_value`, `short_op`, `short_ind`.
- Не указали `value`/`op` — берётся норма сайта.
- `bb` и `ma` сравниваются с ценой: лонг — цена ниже нижней полосы / средней, шорт — выше верхней.
- `all` — все условия сразу («И», до 5), `any` — любое из («ИЛИ», до 4 групп); можно вкладывать.
- Неверные параметры (например `period: 1`) сервер отклоняет — строка попадёт в CSV
  с текстом ошибки `HTTP 400: …` и при продолжении не пересчитывается.
