# gridbacktest — массовые бэктесты сеточного бота

Подбор настроек сеточного бота **Pifagor** на [gridbacktest.com](https://gridbacktest.com/)
не по одной, а сотнями и тысячами. Задаёте, какие пары, периоды, точки входа и параметры
сетки перебрать, — программа сама прогоняет все сочетания на сервере сайта, складывает
итоги в таблицу и показывает лучшие.

Сайт считает каждый прогон по ленте реальных сделок биржи (а не по свечам), так что
результаты здесь — те же, что на сайте, только без ручного перебора.

---

## Возможности

- 🪟 **Окно в стиле сайта** — те же блоки «Пара и период», «Точка входа», «Настройки сетки»,
  те же подписи и пресеты.
- 🔢 **Перебор любого параметра** — у каждого: значение или диапазон «от / до / шаг».
- 🧮 **Счётчик комбинаций на лету** — сколько прогонов выйдет, из чего они складываются и
  сколько это займёт времени.
- 🎯 **Все точки входа** — «всегда в рынке», 16 готовых связок сайта и свои условия из
  24 индикаторов с перебором их настроек.
- ⏸️ **Остановка и досчёт с места** — каждая строка пишется сразу, повторный запуск
  пропускает уже посчитанное.
- 🚦 **Лимиты сервера соблюдаются сами** — программа выдерживает темп, который разрешает
  сайт, и при отказе «слишком часто» ждёт и повторяет.
- 🏆 **Разбор итогов** — лучшие по доходности и просадке, фронт Парето.

## Быстрый старт

1. Установите **Python 3.9+** с [python.org](https://www.python.org/downloads/) — при
   установке отметьте **«Add python.exe to PATH»**.
2. Скачайте проект: зелёная кнопка **Code → Download ZIP** на GitHub (и распакуйте) или
   ```bash
   git clone https://github.com/nbiotminsk/gridbacktest.git
   ```
3. Дважды щёлкните **`gui.bat`** — откроется окно. Нужная библиотека `requests` поставится
   сама при первом запуске.
4. Нажмите **«Войти через Telegram»** и подтвердите вход в боте. Справа вверху должно
   появиться зелёное **«итоги открыты»**.
5. Выберите пары, точку входа, отметьте «перебор» у нужных параметров — и
   **«Запустить прогон»**.

> **Важно.** Итоги сервер отдаёт только после входа через Telegram и при **активном боте
> Pifagor**. Без этого результаты приходят нулями — программа это видит и останавливается.

## Окно программы (`gui.bat`)

### Пара и период

- **Пара** — окно с поиском, как на сайте; можно отметить несколько пар или сразу «Все пары».
- **Сторона** — Long, Short или обе.
- **Период** — даты «с / по» или кнопки «лет 1…6» (последние N лет истории каждой пары).

### Точка входа

Можно включить несколько вариантов — переберутся все:

| кнопка | что делает |
|---|---|
| **Всегда в рынке** | новая сделка сразу после закрытия прошлой; «пауза перезахода» — интервал от 15 минут до суток |
| **Готовые связки** | 16 связок сайта (RSI, MFI, CCI, Bollinger, Supertrend, swing…), интервал свечей и порог swing |
| **Свои условия** | правила из индикаторов в JSON — [см. ниже](#свои-условия-входа) |

### Настройки сетки

Таблица параметров сайта: депозит, плечо, ордеров, перекрытие, коэффициенты цены и
объёма, тейк, реинвест, комиссии. Пресеты **Консервативно / Оптимально / Агрессивно**
подставляют значения сайта.

У каждого параметра:

- **Значение** — одно число или несколько через запятую: `10, 20, 30` (дробные — через точку);
- **перебор** — включает поля **от / до / шаг**: например, перекрытие от 15 до 40 с шагом 5
  даёт 15, 20, 25, 30, 35, 40;
- справа — сколько вариантов даёт строка.

Под таблицей — **счётчик**: например, *«16 524 комбинации — 2 пары × 2 стороны ×
17 входов × 243 набора, ≈ 4.7 сут»*. Если что-то введено неверно, над счётчиком красным
написано, что именно.

### Кнопки

| кнопка | что делает |
|---|---|
| **Запустить прогон** | считает все комбинации; если файл результатов уже есть — спросит, продолжить ли |
| **Продолжить досчёт** | досчитывает оставшееся без вопросов |
| **■ Стоп** | дописывает прогоны, которые уже идут, и останавливается; второе нажатие — сразу |
| **Лучшие результаты** | топ-30 из файла результатов в журнале |
| **Открыть CSV** | открывает таблицу результатов (Excel и т. п.) |
| **Дополнительно…** | имя файла результатов, лимиты скорости, дополнительные периоды, явные наборы `sets`, сохранение и загрузка конфига |

## Сколько это займёт

У сервера жёсткие лимиты: **20 прогонов в минуту и 150 в час**. Программа держит
**18 в минуту и 145 в час**, а при ответе «слишком часто» сама ждёт. Время прогонов она
помнит в `rate.json`, так что перезапуск не обнуляет часовой счёт.

Поэтому потолок — **около 145 прогонов в час**, и параллельные запросы его не поднимают:

| комбинаций | примерно |
|---:|---|
| 100 | 40 минут |
| 1 000 | 7 часов |
| 11 000 (`sweep.json`) | 3 суток |

Счётчик в окне и `--dry-run` в командной строке показывают время заранее. Большой
перебор можно спокойно останавливать и продолжать частями.

## Результаты

Итоги пишутся в **`results.csv`** (имя меняется в «Дополнительно…»), по строке на прогон:
пара, сторона, период, вход, все параметры и итоги — `net_pct` (итог, %), `max_drawdown`
(просадка, %), `liquidated` (была ли ликвидация), число сделок и кругов, комиссии,
фандинг. Рядом лежит `results.jsonl` с полными ответами сервера.

Посмотреть лучшие:

```bash
python gbt.py top results.csv -n 50                # по доходности, без ликвидаций
python gbt.py top results.csv --by max_drawdown    # по наименьшей просадке
python gbt.py top results.csv --with-liq           # вместе с ликвидированными
python analyze.py results.csv                      # подробный разбор
```

`analyze.py` показывает:

- **фронт Парето** — настройки, у которых нет одновременно более прибыльной и менее рискованной;
- **лучшую настройку при просадке не больше 5, 10, 20… %**;
- **топ по отношению «итог / просадка»**;
- **сводку по точкам входа** — сколько настроек выжило и какой лучший итог.

Строки с ошибкой (`HTTP 400` — сервер отклонил параметры) при досчёте не пересчитываются;
сетевые ошибки и сбои сервера — пересчитываются.

## Командная строка и меню

Всё то же самое доступно без окна. **`run.bat`** открывает текстовое меню: вход, пробный
прогон, основной прогон, лучшие результаты. С аргументами передаёт их скрипту:

```bash
python gbt.py login                       # вход через Telegram → session.json (живёт ~неделю)
python gbt.py me                          # проверить вход: статус ботов должен быть active
python gbt.py info                        # пары, связки, индикаторы, лимиты параметров
python gbt.py sweep sweep.json --dry-run  # сколько прогонов и сколько времени
python gbt.py sweep sweep.json            # запустить перебор
python gbt.py top results.csv -n 50       # лучшие результаты
```

Прерывание (**Ctrl+C**) безопасно: запустите ту же команду снова — продолжит с места.
Изменили конфиг — досчитаются только новые комбинации.

### Готовые конфиги

| файл | что перебирает |
|---|---|
| `sweep_test.json` | пробный прогон: BTC, 3 месяца, 3 пресета сайта — 18 прогонов, проверить, что всё работает |
| `sweep.json` | BTC и ETH, 4 года, все связки × сетка параметров |
| `sweep_indicators.json` | BTC, 2 года, свои условия входа из индикаторов × 3 пресета |

## Формат конфига

Окно сохраняет и загружает те же файлы (`sweep_gui.json` пишется при каждом запуске).

| поле | что | пример |
|---|---|---|
| `symbols` | пары или `"all"` | `["BTCUSDT", "ETHUSDT"]` |
| `positions` | `long` / `short` | `["long", "short"]` |
| `periods` | последние N лет пары или даты | `[{"years": 4}, {"from": "2022-01-01", "to": "2024-12-31"}]` |
| `entries` | `none` (всегда в рынке), id связок или `"all"` | `["none", "rsi", "bb"]` |
| `entry_tfs` | интервал связки, мин: 15, 30, 60, 240, 1440 или `"all"` | `[60, 240]` |
| `swing_levels` | порог связки `swing`, % (0.1–50) | `[1, 2, 3]` |
| `chart_tfs` | при `none` — пауза перезахода, мин (или `"all"`) | `[60]` |
| `defaults` | неизменные параметры | `{"deposit": 1000, "leverage": 10}` |
| `grid` | списки значений — перебираются все сочетания | `{"orders": [10, 20], "profit": [0.5, 1]}` |
| `sets` | явные наборы, добавляются к `grid` | `[{"orders": 15, "price_overlap": 25}]` |
| `fees` | комиссии долей единицы (0.0002 = 0.02 %) | `{"fee_maker": 0.0002, "fee_taker": 0.0005}` |
| `indicators` | свои условия входа — см. ниже | |
| `entry_hold` | сколько минут после сигнала вход ещё разрешён | `60` |
| `workers` | параллельных запросов | `2` |
| `rate_per_min`, `rate_per_hour` | потолок прогонов в минуту и в час | `18`, `145` |
| `output` | файл результатов | `"results.csv"` |

Параметры сетки и границы сайта:

| параметр | что | границы |
|---|---|---|
| `deposit` | депозит, $ | 10 – 1 000 000 |
| `leverage` | плечо | 1 – 50 |
| `orders` | ордеров в сетке | 1 – 50 |
| `price_overlap` | перекрытие — на сколько % вниз растянута сетка | 0.1 – 90 |
| `price_factor` | коэффициент цены — разводит уровни к низу сетки | 0.5 – 3 |
| `volume_factor` | коэффициент объёма — растит объём каждого следующего ордера | 0.5 – 3 |
| `profit` | тейк, % | 0.01 – 50 |
| `reinvest` | реинвест, % | 0 / 25 / 50 / 100 |

## Свои условия входа

Кроме готовых связок можно собрать свои правила из 24 индикаторов сайта
(`python gbt.py info` — полный список, параметры и нормы). **Любое поле может быть
списком — переберутся все сочетания.** Пример — `sweep_indicators.json`.

```json
"indicators": [
  {"ind": "rsi",        "period": [7, 14, 21], "value": [20, 25, 30], "tf": [15, 60]},
  {"ind": "supertrend", "period": [7, 10],     "mult": [2, 3],        "tf": 240},
  {"ind": "bb",         "period": [20, 30],    "mult": [2, 2.5]},
  {"ind": "big",        "line": ["250k", "1m"], "value": [20, 40]},

  {"all": [ {"ind": "rsi", "value": 30}, {"ind": "vol_spike", "value": [2, 3]} ]},
  {"any": [ {"ind": "rsi", "value": 30}, {"ind": "drawdown", "hours": 4, "value": [2, 3]} ]}
]
```

Первая строка — это 3 × 3 × 2 = 18 вариантов входа по RSI.

- **Поля:** `period`, `mult`, `line`, `method` (sma / ema / wma), `price`, `hours`, `shift`,
  `tf` (15 / 30 / 60 / 240 / 1440, по умолчанию — `entry_tfs`), `op` (lt / gt / cross_up /
  cross_down), `value`.
- **Лонг и шорт.** `value` и `op` пишутся для лонга, для шорта зеркалятся по норме сайта:
  RSI < 30 → > 70, CCI < −100 → > 100, крупные сделки > 20 → < −20. Где норма одна на обе
  стороны (ADX, всплеск объёма), значение не меняется. `drawdown` в шорте становится
  `runup`, как у связки swing. Свои значения для шорта — `short_value`, `short_op`, `short_ind`.
- Не указали `value` или `op` — берётся норма сайта.
- `bb` и `ma` сравниваются с ценой: лонг — цена ниже нижней полосы или средней, шорт — выше.
- `all` — все условия сразу («И», до 5), `any` — любое из («ИЛИ», до 4 групп); можно вкладывать.
- Неверные параметры (например, `period: 1`) сервер отклоняет — строка попадёт в CSV
  с текстом ошибки.
